## Определение проекта

AI Society Simulation Platform — модульная воспроизводимая исследовательская среда, в которой автономные личности существуют в общем симулируемом мире, воспринимают только доступную часть реальности и принимают решения через сменяемые модели. Платформа моделирует возможности, ограничения и последствия, но не готовые общественные стратегии. Браузерная пиксельная игра является окном наблюдателя, а не владельцем мира.

## Неизменяемые инварианты

- Мир создаёт давление, но никогда не выдаёт задания или стратегии.
- Авторитетное состояние принадлежит headless world kernel.
- Личность, тело, память, знания и отношения отделены от модели.
- Executive Layer — единственный будущий шлюз между LLM и миром.
- Модель возвращает типизированное намерение; движок проверяет и исполняет его.
- Объективное состояние, субъективные знания и представление наблюдателя разделены.
- Наблюдатель read-only по умолчанию; каждое вмешательство становится событием и маркирует запуск.
- Ошибки, забывание и несовершенное знание являются допустимыми свойствами мира.
- Сложные институты не программируются как готовые стратегии.

## Независимые уровни

```text
Research / Observer Interface
Analytics and Reports
Visual Client
Simulation API
Executive Layer
Agent Identity + Memory | Model Provider
Authoritative Event-driven World
Event Log + Snapshots + Replay
```

Зависимости направлены вниз. Аналитика и UI подписываются на данные и не получают скрытого пути изменения ядра.

## Разрешения Preflight

### Событийное время

Приёмочный термин `10 000 тиков` означает **10 000 детерминированно обработанных scheduled events**. Визуальные кадры не имеют отношения к времени мира. Для событий с одинаковым игровым временем порядок определяется монотонным sequence number.

### Детерминированность

- Один централизованный, версионированный PRNG; его состояние входит в snapshot.
- Стабильные идентификаторы создаются из детерминированных последовательностей.
- Каноническая JSON-сериализация использует сортировку ключей и стабильные списки.
- Snapshot хранит очередь, sequence counters, PRNG state и версии схем.
- Event log является append-only hash chain.

### Три режима воспроизводимости

1. World Reproduction: одинаковая конфигурация и seed дают одинаковый исходный мир.
2. Decision Replay: сохранённый поток решений даёт точную историю без сетевых вызовов.
3. Experimental Rerun: модели вызываются заново; расхождение является результатом исследования.

Минимальный Decision Replay обязателен в блоке 4. Branching, сравнение и поиск первой точки расхождения завершаются в блоке 5.

### Пространство и знания

`Tile` хранит только физическое состояние. Исследованность принадлежит `AgentKnowledgeMap`; общей карты знания не существует. Репутация не является глобальным доступным агентам числом: объективны только события, а мнения о репутации хранятся как субъективные beliefs.

### Личность и интеллект

`AgentIdentity`, `AgentBodyState`, `AgentKnowledgeMap` и `MindBinding` являются отдельными моделями. Архитектурный контракт знает уровни `Reactive`, `Scripted`, `Hybrid`, `Full LLM`; блок 1 реализует только deterministic Scripted policy.

### Текст модели

Ответ всегда является строгим структурированным контейнером. Свободное содержание допустимо только в ограниченных типизированных полях (`message`, `terms`, `reason`, `journal_entry`). `reason` — короткое публичное объяснение, не chain-of-thought.

### Договоры и совместные проекты

В MVP появится минимальный `Commitment/Agreement` как версионируемый объект мира: стороны, terms, provenance, status, deadline и события жизненного цикла. Совместный проект хранит участников, вклады и добровольные join/refuse/leave. Богатые институты договоров остаются post-MVP.

### Асинхронные диалоги

Сообщения и ответы не блокируют мир. Контракт событий различает отправку, доставку и истечение; поздний ответ может не достичь получателя. Реализация относится к блокам 2–4.

### Масштабирование

Интерфейсы не должны содержать hardcode на трёх агентов. MVP не оптимизируется под тысячи агентов; scripted acceptance охватывает 1, 3 и 10 агентов, а массовые performance runs отложены.

## Публичные контракты блока 1

- Domain models: мир, клетки, ресурсы, сущности, агент, намерение, результат, событие, запуск.
- Simulation: генератор, планировщик, observation builder, validator/executor, policy interface.
- Persistence: snapshot envelope, canonical hashing, event-chain verification, fixed-root repository.
- API: health, create run, advance run, read run. WebSocket появляется в блоке 3.

## Security baseline

- Все LLM, импортированные и сетевые данные считаются недоверенными.
- Локальный API слушает `127.0.0.1`; внешний доступ потребует authn/authz и TLS.
- Snapshot names валидируются; произвольные пути, pickle, executable YAML и dynamic imports запрещены.
- Model endpoints и credentials в будущем задаются только серверным оператором.
- Скрытые знания не допускаются в prompt, API ответа агента или export без соответствующего профиля.
- Сгенерированный моделями текст экранируется UI и хранит provenance.
